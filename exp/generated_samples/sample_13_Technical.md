## 2. 2. WebRTC 최적화

대규모 버추얼 행사에서 **지연 시간 최소화**를 위한 SFU(Media Server) 구성 방안은 다음과 같이 설계됩니다.  

#### **1. 계층적 SFU 아키텍처**  
- **Edge SFU 클러스터**: 지역별 사용자 트래픽을 분산 처리하기 위해 **지리적 근접성 기반 Edge SFU** 배치  
  - 사용자 → 가장 가까운 Edge SFU로 연결 (Anycast DNS 활용)  
  - 지역별 미디어 트래픽 집중 완화 및 RTT(Round Trip Time) 감소  
- **Core SFU 통합**: Edge SFU 간 미디어 스트림 집계를 위한 중앙 Core SFU 구성  
  - 스트림 복제 및 라우팅을 통해 최종 발신자에게 최적화된 전달 경로 제공  

#### **2. 동적 미디어 전송 전략**  
- **Simulcast/SVC(Scalable Video Coding) 적용**:  
  - 단일 클라이언트가 다중 비트레이트 스트림(예: 240p/720p/1080p) 전송  
  - SFU가 네트워크 상태에 따라 적절한 스트림 선택하여 대역폭 효율성 및 지연 시간 개선  
- **FEC(Forward Error Correction) + Packet Repetition**:  
  - 패킷 손실 시 재전송 대신 사전 보정 데이터 삽입으로 지연 방지  
  - 고손실 구간에서는 제한적 재전송만 허용하여 트레이드오프 관리  

#### **3. 네트워크 최적화**  
- **UDP 기반 QUIC 프로토콜 도입**:  
  - TCP의 Head-of-Line Blocking 문제 해결 및 연결 설정 시간 단축  
  - 다중 스트림 병렬 처리로 전송 효율성 향상  
- **Jitter Buffer 동적 조절**:  
  - 실시간 네트워크 지터 측정 후 버퍼 크기 자동 조정 (기본값: 50~200ms)  
  - 과도한 버퍼링으로 인한 추가 지연 방지  

#### **4. SFU 자원 관리**  
- **Auto-Scaling 정책**:  
  - CPU/메모리/활성화 세션 수 기반 실시간 인스턴스 확장/축소  
  - 예측 가능한 트래픽 피크 대비 사전 확장(Pre-scaling) 적용  
- **부하 분산 알고리즘**:  
  - 사용자 분포, SFU 처리 능력, 네트워크 홉 수를 고려한 최적 라우팅  

#### **5. 모니터링 및 적응형 제어**  
- **실시간 메트릭 수집**:  
  - RTCP Receiver Report(RR)를 활용한 지연 시간, 패킷 손실률, 지터 모니터링  
  - SFU별 처리 지연(Processing Latency) 추적 및 임계값 초과 시 경고  
- **ML 기반 예측 모델**:  
  - 과거 트래픽 데이터 학습을 통한 자원 할당 및 SFU 재배치 전략 수립  

#### **6. 클라이언트-서버 협업**  
- **ICE 후보 최적화**:  
  - TURN 서버 우선순위 조정으로 연결 설정 시간 단축  
  - 호스트 후보(Host Candidate) 우선 사용으로 NAT 통과 지연 감소  
- **BWE(Bandwidth Estimation) 강화**:  
  - GCC(Google Congestion Control) 알고리즘 개선으로 네트워크 혼잡 사전 감지  

---  
이 방안은 **SFU의 분산 처리 능력**과 **실시간 네트워크 적응 메커니즘**을 결합하여, 대규모 행사에서도 **100~300ms 수준의 지연 시간**을 유지할 수 있도록 지원합니다.

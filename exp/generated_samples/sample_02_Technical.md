## 2. 2. 데이터 파이프라인

IoT 센서 데이터의 실시간 처리 파이프라인은 **수집 → 전송 → 처리 → 저장 → 분석** 단계로 구성되며, 확장성과 안정성을 보장하기 위해 분산 시스템을 기반으로 설계됩니다.  

- **IoT 디바이스 인터페이스**: MQTT/HTTP/CoAP 프로토콜을 통해 센서 데이터를 수집하며, 경량화된 JSON 또는 Protobuf 형식으로 직렬화하여 네트워크 부하 최소화.  
- **에지 컴퓨팅 노드**: 로컬 전처리(필터링, 압축, 이상치 제거)를 수행하여 클라우드 전송량 감소. 컨테이너 기반 마이크로서비스로 구현되어 유연한 배포 지원.  

- **Apache Kafka 활용**:  
  - **고성능 스트리밍**: 파티션 기반 병렬 처리로 초당 수십만 메시지 처리 가능.  
  - **지속성 보장**: 디스크 기반 메시지 저장 및 복제(Replication)를 통해 데이터 유실 방지.  
  - **보안 통합**: TLS 암호화 + SASL/SCRAM 인증으로 전송 계층 보안 강화.  
- **Dead Letter Queue(DLQ)**: 처리 실패 시 별도 토픽으로 라우팅하여 재처리 메커니즘 적용.  

- **Spark Streaming/Flink**:  
  - **마이크로배치 또는 이벤트 타임 처리**: 100~500ms 지연 시간으로 실시간 분석 지원.  
  - **스트림-배치 통합**: Structured Streaming을 활용해 배치 작업과 동일한 로직 재사용.  
  - **머신러닝 통합**: PySpark MLlib 또는 TensorFlow Serving을 통해 실시간 예측 모델 적용 (예: 이상 감지, 장비 고장 예측).  
- **창(Window) 기반 집계**: 1분/5분/1시간 단위 롤링 윈도우로 시계열 데이터 분석.  

- **다양한 스토어 연동**:  
  - **원시 데이터**: Amazon S3/HDFS에 시계열별 파티션 저장 (장기 보관용).  
  - **가공 데이터**:  
    - **시계열 DB**(InfluxDB, TimescaleDB): 실시간 쿼리 최적화.  
    - **NoSQL**(Cassandra, DynamoDB): 고속 쓰기/읽기 지원.  
  - **구조화된 데이터**: 데이터 웨어하우스(Redshift, BigQuery)로 집계 결과 적재.  
- **데이터 라이프사이클 관리**: TTL(Time-To-Live) 정책 및 계층화 스토리지(핫/콜드 데이터 분리) 적용.  

- **실시간 대시보드**: Kafka Streams + Grafana/Kibana로 센서 상태 모니터링.  
- **배치 분석**: Spark SQL 또는 Presto를 이용해 일일/주간 리포트 생성.  
- **알림 시스템**: 임계치 초과 시 Slack/MS Teams로 자동 알림 전송.  

- **자동 복구 메커니즘**:  
  - Kafka Consumer Offset 관리 + Spark Checkpointing으로 장애 발생 시 상태 복구.  
  - Kubernetes 기반 오케스트레이션으로 컨테이너 자동 재시작.  
- **성능 모니터링**: Prometheus + Grafana로 파이프라인 지연 시간, 처리량, 에러율 추적.  
- **데이터 유효성 검증**: Great Expectations 등을 활용해 수집/처리 단계의 데이터 품질 보장.  

- **E2E 암호화**: 전송 중(TLS) 및 저장 시(AES-256) 데이터 암호화.  
- **접근 제어**: IAM 역할 기반 권한 관리 + Kafka ACL로 토픽별 접근 제한.  
- **GDPR/CCPA 대응**: 개인 정보 마스킹 및 데이터 삭제 정책 적용.  

이 아키텍처는 **초당 10만~100만 이벤트 처리**를 목표로 설계되며, 클라우드/온프레미스 하이브리드 환경에 유연하게 적용 가능합니다.
